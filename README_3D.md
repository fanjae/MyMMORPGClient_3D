# 3D 클라이언트 실행

2026-10-15: 3D game protocol **12**, Login protocol 2. 최신 서버와 함께 실행한다. 2D 클라이언트는 기존 protocol 6을 유지한다.

## 씬과 실행 파일

- Unity 6000.3.7f1에서 `Assets/Scenes/SampleScene.unity`를 연다.
- 지형·시작 위치·클라이언트·입력 진단 컴포넌트·인벤토리 Canvas·EventSystem이 씬에 저장되어 있다.
- `Tools > MyMMORPG > Place Inventory and Input Probe`는 빠진 UI만 추가하며 기존 지형을 다시 생성하지 않는다.
- `Tools > MyMMORPG > Build 3D Windows Client`로 `Builds/Movement3D/MyMMORPGClient_3D.exe`를 만든다.
- 실행 파일과 `_Data`, `UnityPlayer.dll`, `MonoBleedingEdge` 등 빌드 디렉터리를 함께 사용한다.
- `Offline preview`는 DB 없이 씬 지형과 샘플 인벤토리·몬스터를 확인한다. 온라인에서는 서버 지형과 서버의 몬스터 상태를 사용한다.

## 조작

| 입력 | 동작 |
|---|---|
| WASD / 방향키 | XZ 이동 |
| Space | 지상에서 새 입력으로 점프 |
| J / 왼쪽 Ctrl / 하단 ATTACK | 기본 근접 공격 |
| I / Inventory 버튼 | 인벤토리 열기·닫기 |
| Esc | 채팅 포커스·인벤토리 정리 후 채널/게임 메뉴 열기·닫기 |
| Z / LOOT | 가까운 드롭 획득 |
| R | 오프라인 위치 초기화 |

인벤토리 창이 열려 있거나 텍스트 입력 중이면 캐릭터 입력을 차단한다. 창 비활성화·맵 이동 시 대기 입력을 지운다. Windows 접근성 입력처럼 Unity 창 키 이벤트만 전달하는 입력도 지원한다. 매우 짧은 이동 입력은 다음 고정 이동 단계까지 보존한다.

## 기본 공격과 하단 HP·MP

J 또는 왼쪽 Ctrl을 새로 누르거나 하단 ATTACK 버튼을 클릭하면 검을 휘두른다. 누른 채 유지하는 입력은 연속 공격으로 처리하지 않는다. 서버는 0.5초 간격, 전방 3m·높이 차이 1.5m 이내, 지형에 가려지지 않은 가장 가까운 몬스터 한 마리에 20 피해를 적용한다. 슬라임은 HP 60이며 세 번 적중하면 사망하고 5초 후 재생성된다. 기본 공격의 MP 소모는 0이다.

검 표시는 입력 즉시 재생하지만 피해·HP·사망은 서버 응답으로 확정한다. 인벤토리·채팅·창 비활성화·Map 전환 중에는 공격을 차단한다. 하단 HP·MP 숫자와 게이지는 인벤토리를 닫아도 표시되며 서버의 캐릭터별 DB 상태를 사용한다. 물약 사용이 확정되면 두 UI가 함께 갱신된다. 씬의 `Player Vitals HUD`에서 배치를 조정할 수 있다.

패킷이 변경되어 서버와 3D 클라이언트를 모두 version 12로 빌드해야 한다. 기존 DB에는 003_field_combat.sql, 004_field_recovery.sql, 005_trade.sql도 적용한다. [서버 판정과 검증 기록](../MyMMORPGServer/docs/BASIC_ATTACK_3D.md)을 참고한다.

## 인벤토리

장비·소비·설치·기타·캐시의 5개 탭, 탭당 24칸, 샘플 아이템 8종, 수량·설명·메소·HP/MP 표시를 제공한다. 드래그로 같은 탭 안의 슬롯 이동·교환·병합, SORT로 정렬·동일 아이템 병합, 포션 더블클릭 또는 USE로 HP/MP 회복이 가능하다. 회복 수치가 가득 차면 수량을 소모하지 않는다.

온라인에서는 서버가 조작과 수량을 검증하고 **MySQL의 캐릭터별 인벤토리·슬롯 테이블**에 저장한다. 슬롯 변경·포션 소비·HP/MP·revision을 하나의 트랜잭션으로 처리한다. 기존 DB에는 서버 저장소의 `database/init/002_inventory.sql`을 적용해야 한다. 현재 장비·복구·거래에는 003/004/005 SQL과 protocol 12 실행 파일이 필요하다. 오프라인 프리뷰의 조작은 온라인 캐릭터에 반영하지 않는다. 무기·모자 착용/해제와 몬스터의 기본 물약 드롭 획득을 지원한다. 장비는 고유 인스턴스 ID를 유지한다. EQUIP 또는 장비 더블 클릭으로 착용하고 EQUIPMENT 창의 UNEQUIP으로 빈 슬롯에 해제한다. 목검은 공격력 +5, 모자는 몬스터 피해 -2다. 임의 아이템 삭제는 후속 기능이다. 스키마 적용과 검증은 [INVENTORY_DATABASE.md](../MyMMORPGServer/docs/INVENTORY_DATABASE.md)를 참고한다.

## 플레이어 간 거래

TRADE에서 같은 채널·맵의 상대를 선택해 REQUEST를 누르면 상대가 ACCEPT할 수 있다. 거래를 수락하면 양측 이동·공격과 인벤토리 변경을 제한한다. INVENTORY에서 슬롯을 선택하고 수량을 입력한 뒤 ADD SELECTED로 최대 6개 슬롯을 제안한다. SET MESOS로 메소를 등록하고 양측 FINAL CONFIRM으로 교환한다. 제안 변경 시 양측 확인을 초기화한다. 착용 중 장비는 먼저 해제해야 한다.

양측 인벤토리·메소·장비 소유권과 거래 기록을 하나의 DB 트랜잭션으로 확정한다. 확정 중에는 취소하지 않으며 QUERY로 결과를 확인한다. 미확정 거래 번호를 로컬에 저장해 같은 서버·캐릭터로 재접속하면 결과를 조회한다. 완료 기록은 서버 재시작 후에도 조회할 수 있다. 초대는 30초, 편집은 2분 후 만료한다. 확정 중 DB 오류는 같은 거래 번호로 재시도한다.

## 핑·지터에 따른 상대 이동 표시

1초 간격의 왕복 측정과 실제 이동 행동의 수신 간격으로 표시 버퍼를 200~400ms 사이에서 조절한다. RTT 변동과 도착 지터가 커지면 빠르게 늘리고 안정화되면 천천히 줄인다. 일정하게 높은 RTT 자체를 같은 크기의 표시 지연으로 더하지 않는다. 본인 이동의 즉시 반응은 유지한다.

기존 1초 체크포인트 이후 추가 예측은 RTT에 따라 100~200ms로 제한한다. 서버 보정·맵 이동·재접속 시 이전 이동 상태를 정리한다. TRADE 버튼 아래에 RTT와 현재 표시 버퍼를 표시한다. [구현·검증 기록](../MyMMORPGServer/docs/FIELD_TRADE_TIMING_VALIDATION_2026-10-15.md)을 참고한다.

## 몬스터

3D 맵 100000002/100000003에 서버가 순찰하는 기본 슬라임 3마리를 만든다. 같은 맵의 모든 캐릭터에게 동일 tick의 몬스터 ID·XYZ·방향을 최대 200ms 주기로 전달한다. 동일 상태는 1초 확인 주기를 사용하며 32마리 초과 필드는 반경 16m의 목록을 32개씩 나누어 전송한다. 늦게 입장한 캐릭터도 현재 상태를 받는다. Map 변경·재접속 시 이전 몬스터를 제거하고 새 generation의 상태만 적용한다. 기본 공격에 따른 HP 감소·피격 수치·사망·5초 후 재생성을 공유한다. 몬스터는 6m 안의 살아 있는 플레이어를 추적하며 약 1.2m 거리에서 1.5초마다 10 피해를 준다. 사망 시 빨간 물약 한 개를 60초 동안 드롭한다. Z 또는 LOOT로 2m 안의 드롭을 획득한다. HP 0에서는 이동·공격·물약 부활이 제한되며 ESC 메뉴에서 3초 후 필드 시작 위치로 부활한다.

## 씬 UI와 채널

로그인·캐릭터 선택·채팅·필드 이동·ESC 메뉴는 씬에 배치한 UGUI로 조작한다. OnGUI는 Windows 키 이벤트 보완에만 사용한다. ESC 메뉴의 CH 1/2/3에서 채널을 선택하며 EXIT GAME으로 게임을 종료한다. 같은 채널의 같은 필드만 캐릭터·몬스터·드롭·일반 채팅을 공유한다. 채널 이동은 살아 있는 지상 캐릭터만 가능하며 5초 간격이다. 같은 필드의 위치와 인벤토리·장비는 유지한다. 재접속은 채널 1에서 시작한다. 기존 채널 기능은 보존하고 추가 채널 구현은 확인 사항이 정리될 때까지 대기한다.

[10월 13일 구현과 채널 구조 검토](../MyMMORPGServer/docs/FIELD_EXPANSION_2026-10-13.md)를 참고한다.

## 검증

서버 저장소에서 `Tests/NetworkReliability/RunFieldFeatures.ps1`로 DB 없는 인벤토리 규칙·몬스터 공유 TCP 검사를 반복한다. `RunMovement3D.ps1`은 기존 이동과 세 지연 조건 검사다. `RunFull3DIntegration.ps1`은 InventoryDatabase 검증 프로그램과 임시 MySQL, 실제 LoginServer/GameServer·두 Unity Player를 사용해 DB 저장·동시 소비·롤백·연결을 확인한다. 검사 후 이번에 시작한 프로세스·컨테이너만 종료한다.

실제 창 입력을 기록하려면 다음처럼 실행한다. 이 옵션은 입력을 생성하지 않는다.

```powershell
.\Builds\Movement3D\MyMMORPGClient_3D.exe --offline-preview --input-probe
```

`Logs/input-probe.json`에 입력 횟수·점프 ID·좌표·포커스·씬 지형 사용 여부가 기록된다. `--smoke-test` 등의 자동 이동 옵션과 함께 실행하지 않는다. 사람이 길게 키를 누르는 동작, 공중 반복 입력과 누른 채 착지하는 동작은 실제 키보드로 별도 확인할 수 있다.

## 10월 12일 입력·복구 보완

채팅·인벤토리·비활성화·Map 전환 중 눌린 키는 떼기 전까지 이동에 재사용하지 않는다. Esc는 채팅 포커스를 해제한다. 인벤토리 응답이 5초 동안 없거나 저장 오류가 발생하면 변경 조작을 막고 조회만 최대 3회 재시도한다. REFRESH 버튼으로 수동 조회도 가능하며 물약 사용 요청을 자동 재전송하지 않는다. 온라인 상태를 표시한 뒤 오프라인 프리뷰로 전환하면 별도 샘플 인벤토리로 초기화한다.

몬스터는 수신 상태 사이를 보간하고 큰 위치 차이는 즉시 맞추며, 수신이 끊기면 마지막 상태에서 멈춘다. 공통 재질·카메라·슬롯 표시를 재사용해 반복 갱신 비용을 줄였다.

서버의 RunFull3DIntegration.ps1은 실제 슬롯 조작과 두 서버 재시작까지 검증한다. -ManualInput 모드는 테스트 계정으로 창 두 개를 표시하며 자동 이동을 사용하지 않는다. 출력한 검사 디렉터리의 manual-finish 파일이 있으면 종료하며, 실제 점프 기록 없이 완료되면 실패한다. input-probe.json과 input-probe-events.jsonl에 mode=manual인 실제 키 입력 상태를 남긴다.

변경 내용·측정 범위·다음 기능 설계는 [10월 12일 보완 기록](../MyMMORPGServer/docs/FIELD_HARDENING_2026-10-12.md)을 참고한다.

## 확장 검사 실행

서버 저장소에서 RunFull3DIntegration.ps1 -FieldExpansion은 기존 전체 연결·재시작 검증 후 채널·장비·동시 획득·사망/부활을 검사한다. -ManualInput -ManualCombat은 임시 지형 복사본에서 몬스터 앞에 두 창을 배치하고 검사용 HP 5000을 사용한다. 원본 지형과 기존 DB는 변경하지 않는다.

--field-load=3 / 32 / 128은 오프라인 순찰·피해 숫자·공격 표시를 자동 재생하는 부하 검사다. 3초 준비 후 12초 동안 프레임·메모리를 측정하고 Logs/field-load-N.result 및 화면 PNG를 남긴다. 실제 입력 기록과 구분하며 FPS 제한을 해제한 전체 프레임 시간으로 GPU 단독 시간을 뜻하지 않는다.

## 10월 13일 오류 복구와 주변 표시

피격 DB 결과가 불명확하면 이동·공격·맵 이동을 멈추고 저장 상태를 복구한 뒤 재개한다. 피격 처리 번호를 DB에 남겨 같은 피해를 두 번 적용하지 않는다. 사망 중에도 I로 인벤토리를 열 수 있으며 물약 사용 버튼은 비활성화한다. 중단 중 누른 키와 대기 공격은 복귀 후 재사용하지 않는다.

드롭 획득 응답을 잃으면 지급을 다시 요청하지 않고 결과를 최대 3회 조회한다. 미확정 드롭 번호는 서버 주소·로그인 포트·캐릭터별로 보관하여 재접속에서도 조회한다. LOOT 또는 Z로 결과 조회를 다시 시작할 수 있다. 보관된 기록이 없으면 인벤토리를 확인하도록 안내한다. 획득·피격 기록은 30일 보관한다.

몬스터 목록은 모든 조각이 도착한 뒤 한 번에 화면에 반영한다. 주변 드롭도 16m 반경의 목록이 달라질 때만 갱신하며 진입·이탈을 반영한다. 플레이어 이동과 일반 채팅의 기존 공유 범위는 유지한다.

RunFull3DIntegration.ps1 -FieldRecovery는 임시 DB에 피격 SQL 오류를 주입해 전투 중단·맵 이동 거절·피해 한 번 적용·복구 후 재개를 검사한다. -FieldExpansion과 함께 사용하면 장비·획득 결과 조회·사망/부활도 확인한다. 기존 사용 DB에는 자동 적용하지 않는다.
